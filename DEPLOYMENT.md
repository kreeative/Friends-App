# Deployment and Supabase ↔ Netlify setup

This document explains how to finish deploying Rich & Friends when using Supabase for data/auth and Netlify for static hosting.

Preview (PR): https://deploy-preview-1--richandfriends.netlify.app
Netlify deploy log: https://app.netlify.com/projects/richandfriends/deploys/6a71f00d1d31be0008b1968a

Summary

- The preview site shows "SUPABASE IS NOT CONFIGURED" when VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY are not available at build time.
- Vite inlines VITE_* env vars during the build. After you set or change them in Netlify you must trigger a new deploy.
- Do NOT commit secret keys to the repo. The anon key is public-facing (it belongs in the client bundle) but treat service-role keys and other secrets carefully.

Steps to finish setup

1) Create or locate a Supabase project

- Open https://app.supabase.com and select or create a project.
- In the project: Settings → API → copy:
  - Project URL (e.g. https://your-project.supabase.co)
  - anon public key (the "anon" key under Project API keys)

2) Set Netlify environment variables

- Open Netlify → Site: richandfriends → Site settings → Build & deploy → Environment → Environment variables.
- Add the following keys (exact names):
  - VITE_SUPABASE_URL = https://YOUR-PROJECT.supabase.co
  - VITE_SUPABASE_ANON_KEY = <your-anon-key>

Notes:
- Use the full https:// URL including the .supabase.co host.
- The anon key is safe to ship in the client bundle; it only has whatever RLS policies permit.
- If you change either variable, trigger a redeploy (Deploys → Trigger deploy → Deploy site).

Via the Netlify CLI (alternative):

```bash
npm i -g netlify-cli
netlify login
netlify link # if site not linked locally
netlify env:set VITE_SUPABASE_URL "https://YOUR-PROJECT.supabase.co"
netlify env:set VITE_SUPABASE_ANON_KEY "your-anon-key"
netlify deploy --prod    # or trigger a branch/deploy-preview build
```

3) Add the deployed site URL to Supabase redirect list

- In Supabase: Authentication → Settings → URL Configuration.
- Add both your production preview site and localhost (for local dev). Example:
  - https://deploy-preview-1--richandfriends.netlify.app
  - http://localhost:5173

4) Optional: confirm Supabase attachments / Edge Functions

- If you attached the Supabase project to the repo via the Supabase UI (or used Supabase's "Attach repository" flow), that helps deploying functions and managing secrets. You still need to add the VITE_* vars on Netlify.
- Deploy scheduled Edge Functions (if you use the notify job):
  - supabase functions deploy notify --no-verify-jwt
  - supabase secrets set RESEND_API_KEY=... MAIL_FROM="Friends <hi@yourdomain>"

Why you saw "SUPABASE IS NOT CONFIGURED"

- The client checks for VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY at runtime (build-time actually for Vite). If they are absent the app shows a friendly message telling you to copy .env.example → .env and set the vars. The Netlify build did not have those env vars set when the preview was built.

Troubleshooting

- After adding the env vars, trigger a deploy and then clear any CDN caches (Netlify handles this automatically for new deploys).
- If auth redirects fail, double-check the Redirect URLs in Supabase include the deployed URL.
- If you still see the message after a fresh deploy, confirm the Netlify site is building the same branch/commit as the preview (PR preview vs production branch builds differ).

Security note

- The anon key is intended to be public-like and used by the client; do not commit service-role keys or other secrets to the repository.
